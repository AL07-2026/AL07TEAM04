# 가입·프로필 보안 규칙 복구

- 이전 실제 규칙: `b48d1367-2925-4517-88da-f4ba9edbd1e0`. 모든 클라이언트 읽기·쓰기를 2026-09-06 전까지만 허용하는 임시 규칙이었다. 확인 시점에는 만료되어 전부 거부 상태였다.
- 전체 공개 기한을 연장하지 않는다. `users`, `company_profiles`, `senior_profiles`, `companies`, `experience_cards`만 본인 소유 데이터 중심으로 복구한다.
- 사용자 문서 역할은 senior/company만 허용하고 기존 역할 변경, 타인 이메일, 관리자 필드 추가를 거부한다. 관리 권한은 서버 발급 커스텀 클레임으로만 판단한다.
- 프리미엄 신청/무료 횟수/공개 목록/감사 이력은 직접 접근 금지, 인증된 서버 API만 사용한다.
- 다른 컬렉션의 기존 거부 상태는 유지한다. 공고·제안의 직접 저장 기능까지 복구한 것은 아니다. 공통 API의 비공개 공고 검색 필터를 먼저 배포해야 해당 영역의 권한을 안전하게 확장할 수 있다.
- `scripts/verify-profile-rules.mjs`로 Firebase Rules 공식 테스트 API에 인라인 데이터만 전달: 40개 모두 SUCCESS, 컴파일 이슈 없음. 실제 문서·파일·규칙을 변경하지 않는 사전 검사다.
- 테스트 문서: https://firebase.google.com/docs/reference/rules/rest/v1/projects/test
- 범위 지정 배포만 사용한다. 보안 규칙은 미리보기 채널과 운영에서 공유된다.
- 예전 만료 규칙으로 복귀하면 가입·프로필이 다시 차단된다. 장애 시 전체 공개 대신 구체적 거부 사례를 추가 테스트한 뒤 최소 권한으로 수정한다.
