# 프리미엄 신청·승인·노출 연결

## 정책

- 기업 계정(uid)별 무료 프리미엄 노출 3회. 동일 사업자 여러 계정의 통합 한도는 아직 제공하지 않는다.
- 접수, 수정, 보완 요청, 반려, 재제출은 차감하지 않는다.
- 운영 관리자 또는 최고 관리자가 승인할 때 신청 상태, 공개 목록, 사용 횟수, 검토 이력을 하나의 서버 트랜잭션으로 저장한다.
- 승인 시 미래의 노출 종료 일시를 관리자가 지정한다. 고정 노출 기간은 임의로 정하지 않았다.
- 한 계정은 한 번에 하나만 노출한다. 종료 이후 남은 횟수로 재신청한다. 조기 종료는 환급하지 않는다.
- 과거 승인 건은 최소 1회 사용으로 인정한다. 신청 데이터 삭제로 사용 횟수를 초기화할 수 없다.
- 공개 목록은 승인된 유효 기업을 먼저 반환하며 기존 샘플로 보충한다. 프로젝트 상단과 롤링 배너는 기존 최대 4개 선정 구조, 전체 목록은 최대 50개다. 승인 기업 모두의 배너 노출 빈도 보장은 하지 않는다.

## 구현

- 기업 프로젝트 화면: 잔여 횟수, 기존 내용 수정, 대표 사진, 검토 의견, 노출 종료일, 상태 새로고침.
- `/admin/premium`: 신청 목록 25개씩 조회, 보완 요청/반려/승인/노출 종료. 조회·재무 관리자는 변경 불가.
- `premium_company_applications`: 계정당 최신 신청, 수정 버전.
- `premium_company_entitlements`: 서버 전용 사용 횟수.
- `premium_company_listings`: 공개에 필요한 정보만 복사. 개인 연락처 제외.
- `premium_company_reviews`: 승인 주체·결정·시점·버전의 별도 감사 이력.
- 사진: 인증된 계정의 Storage 경로에 JPG/PNG/WEBP 최대 2MiB 저장. 확장자만 믿지 않고 바이너리 시그니처 확인. SVG 차단. DB 저장 실패 시 새 파일 정리 시도.
- 사진 URL·업로더·회사 정보·관리자 ID는 요청 본문을 신뢰하지 않고 서버에서 결정한다.
- 낡은 수정 버전, 중복 승인, 동시 승인, 4번째 무료 사용은 서버에서 거부한다. 계정 변경 시 브라우저의 비공개 상태를 초기화한다.

## 검증

- `npm run validate`: 타입·린트·58개 파일/561개 테스트·빌드 통과. 기존 번들 크기 경고와 jsdom 미구현 안내는 유지.
- 순수 정책 테스트, 트랜잭션을 모사한 인메모리 저장 테스트, 요청 권한/사진 실패 복구, 기업·관리자 컴포넌트 테스트 포함. 실제 Firestore 동시성 부하 시험은 아니다.
- 실제 브라우저: 로컬 랜딩→더보기→프로젝트→비로그인 내 정보→로그인 이동 확인. 기본 데스크톱 및 390px 폭에서 일반 화면 확인. 로그인한 기업/관리자 전체 흐름은 모의 테스트로만 검증.
- 운영 데이터에 시험 신청/승인/파일/메일을 생성하지 않았다. 실제 계정의 사진 업로드와 관리자 승인은 배포 후 별도 실사용 검증 필요.

## 남은 제한

- 사진은 완전한 픽셀 디코딩·악성 파일 검사·자동 리사이즈를 하지 않는다. 기존 교체 사진과 탈퇴 계정 이미지의 자동 수명주기 정리는 후속 작업이다.
- 자동 승인·관리자 이메일 알림은 제공하지 않는다. 기업은 상태 새로고침으로 결과를 확인한다.
- 일반 채용공고의 동일 제목 ID 충돌/삭제 재등장/첨부 기능은 이 프리미엄 변경으로 해결되지 않는다.
- 공통 API의 Gmail Secret 누락 및 비공개 공고 검색 필터 미배포 문제는 유지. 메일을 임의 비활성화하지 않는다.
- 프론트엔드는 leedongwook 채널 전용. premiumApi와 Firestore 규칙은 운영과 공유되므로 해당 부분은 양쪽에 영향을 준다.

## 실사용 확인 순서

1. 기업 로그인 후 기업 프로필을 저장하고 프로젝트 화면의 무료 잔여 3회를 확인한다.
2. 사용 권한이 있는 기업 사진과 소개를 접수한다. 잔여 횟수는 유지되어야 한다.
3. 운영 관리자가 보완 의견을 저장한다. 기업에서 새로고침 후 사진/문구 수정 및 재제출한다.
4. 관리자 승인 시 종료 일시를 지정한다. 잔여 2회, 공개 기업 목록 반영을 확인한다.
5. 노출 중 추가 신청 차단과 종료 후 다음 신청을 확인한다. 실제 시험 승인은 무료 횟수를 소비하므로 사용자와 합의한 계정에서만 수행한다.

배포 결과는 `AI_COLLABORATION_LOG.md`의 최신 항목을 따른다.
