# ECC TDD Workflow Skill

기능 개발 시 테스트를 우선 설계하고, 안전하고 신속하게 구현하여 회귀 버그를 원천 차단하는 TDD 가이드라인입니다.

## 1. TDD 워크플로우 사이클
1. **[Red] 실패하는 테스트 작성**:
   - 구현하고자 하는 함수의 인터페이스를 정의하고, 기대 결과와 엣지 케이스를 담은 단위 테스트 작성 (`*.test.ts`)
2. **[Green] 최소한의 코드로 테스트 통과**:
   - 테스트를 통과시키는 가장 간결하고 정확한 프로덕션 코드 구현
3. **[Refactor] 리팩터링 및 최적화**:
   - 가독성 향상, 중복 제거, 성능 최적화를 수행하며 모든 테스트가 계속 녹색(Pass)인지 검증

## 2. 테스트 작성 원칙
- **AAA 패턴 (Arrange - Act - Assert)**: 테스트 코드를 준비, 실행, 단언 3단계로 명확히 구조화합니다.
- **외부 의존성 격리**:
  - `vi.mock`을 사용하여 외부 네트워크 및 Firebase SDK를 격리합니다.
  - 테스트 간 상태 오염을 방지하기 위해 `beforeEach(() => { vi.clearAllMocks(); })`를 사용합니다.
- **경계값 검증**:
  - `0`, 음수, 빈 문자열(`""`), 빈 배열(`[]`), `null`, `undefined`, 매우 큰 숫자 등 극단적 경계값 테스트 케이스를 필수로 추가합니다.
